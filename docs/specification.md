## 1. プロダクト概要

### 1.1 コンセプト

「言葉の実験室」は、Word2Vecの単語ベクトルを、検索結果だけでなく計算過程や座標まで観察できる教育・実験用アプリである。主な価値は次の3点に置く。

1. ある単語から別の単語へ、関連語をたどって到達するA*連想探索を実行し、探索の広がりを逐次可視化する。
2. 単語ベクトルの加算・減算、スカラーによる乗算・除算を試し、結果に近い単語を確認する。
3. 各単語のベクトル値、統計量、距離、近傍、2D/3D上の配置を横断的に観察する。

本アプリは「単語の本当の意味」や「人間の思考過程」を表示するものではない。コーパス内の共起傾向から得られた分布表現を操作・観察するツールである。

### 1.2 優先順位

優先順位は次のとおりとする。

1. 探索が成功・失敗・中断のいずれで終わったかを正しく説明できること。
2. ゴールへ至るまでの候補展開、採用経路、スコア変化を観察できること。
3. 同一条件なら再現可能であること。
4. ベクトル演算や編集が元モデルを破壊しないこと。
5. 大規模モデルでもUIが固まらず、処理を中断できること。

### 1.3 対象ユーザー

- Word2Vecやベクトル表現を学ぶ人
- 日本語コーパスの語彙傾向を観察したい人
- 単語間の連想経路やアナロジーを試したい開発者・研究者
- 動画や授業で結果を見せたい説明者

### 1.4 スコープ外

初版では以下を実装しない。

- ブラウザ上でのWord2Vec再学習
- 文脈依存埋め込みや文章埋め込みへの一般化
- 複数ユーザーの認証、権限管理、クラウド共同編集
- 単語同士の要素積・要素除算を通常の意味演算として提供すること
- 探索結果が言語学的、心理学的、社会的に正しいという保証
- モデルや学習コーパスの自動取得・無断再配布

## 2. 用語と基本定義

| 用語 | 定義 |
|---|---|
| 語彙 | モデルが保持するキーの集合。単語以外のトークンを含む場合がある |
| 単語ベクトル | 語彙キーに対応する有限次元の実数ベクトル |
| OOV | Out of Vocabulary。モデル語彙に存在しない入力 |
| 近傍 | 指定された類似度とフィルター条件で得た上位 `k` 語 |
| 探索グラフ | 各語から近傍語へ有向辺を張った暗黙グラフ |
| 探索セッション | A*探索1回分の設定、イベント、結果、キャンセル状態 |
| 実験セッション | 元モデルを変更せず、ベクトル差分を一時的に保持する領域 |
| 基底モデル | 実験編集を適用する前の読み取り専用モデル |
| 射影 | 選択した高次元ベクトル群を2Dまたは3Dへ変換した表示用座標 |

類似度の既定値はコサイン類似度とする。非ゼロベクトル `x`, `y` に対して次を用いる。

```text
cos(x, y) = (x · y) / (||x||₂ ||y||₂)
cosine_distance(x, y) = 1 - cos(x, y)
angular_distance(x, y) = arccos(clamp(cos(x, y), -1, 1)) / π
```

`angular_distance` は0から1の範囲であり、正規化された非ゼロベクトル上で距離として扱える。ゼロベクトルに対するコサイン・角距離は未定義とし、APIは検証エラーを返す。

## 4. 画面・UX仕様

### 4.1 全体レイアウト

デスクトップでは、上部バー、左側の機能ナビゲーション、中央キャンバス、右側インスペクターの4領域を基本とする。

- 上部バー：アプリ名、現在のモデル、実験セッション、モデル状態、設定
- 左ナビゲーション：連想探索、ベクトル演算、単語詳細、距離比較、可視化、モデル管理
- 中央：機能ごとの主表示
- 右インスペクター：選択語、スコア、ベクトル統計、編集差分、警告

幅が狭い場合、右インスペクターはドロワーへ切り替える。A*のグラフ操作はマウスだけでなく、ノード一覧とタイムラインからキーボードでも選択可能にする。

### 4.2 共通入力

- 単語入力は前後空白を除去するが、勝手な小文字化、Unicode正規化、表記変換は行わない。
- モデル固有の正規化が必要な場合は、モデルメタデータの `normalization_policy` として明示し、候補変換はユーザーに提示してから適用する。
- 入力中は語彙前方一致候補を最大20件表示する。
- OOV時は「モデルに含まれない」こと、候補語、利用中モデルを表示する。
- エラーは入力欄付近の説明と、詳細を開けるエラーIDの両方を示す。

### 4.3 連想探索画面

#### 入力

- 開始語
- 目標語
- 近傍数 `k`：既定25、許容2〜200
- 1手あたり固定ペナルティ `lambda`：既定0.15、許容0〜1
- 最大展開数：既定5,000
- タイムアウト秒：既定30秒
- progressive widening：既定ON、段階 `[10, 25, 50, 100]`
- 除外語、正規表現、最小頻度、同一表記除外などのフィルター
- 近傍方式：`exact` または `ann`
- ランダムシード：確率的処理を併用する場合のみ使用

#### 実行中表示

- 現在展開中のノード
- open set、closed setの件数
- 発見済みノード数・辺数
- 現在の最良候補と目標までの角距離
- 経過時間・展開数・設定上限
- 一時停止、再開、1ステップ実行、キャンセル
- 速度調整：イベントをすべて保持したまま描画間隔のみ変更

#### グラフ表現

- 開始語：青、目標語：金、展開済み：灰、open set：水色、現在ノード：橙、最終経路：緑、棄却・更新前の親辺：薄灰
- ノードサイズ：既定では目標への近さ。切替で出現頻度または一定サイズ
- 辺ラベル：遷移コスト、コサイン類似度
- hover：`g`, `h`, `f`, 深さ、親、発見順、展開順
- click：右インスペクターに単語詳細を表示
- 最終経路以外を薄くするフォーカス切替
- 大量ノード時は描画上限を設けるが、データ自体は失わない。非表示数を明示する。

#### タイムライン

イベントを時系列で表示し、任意時点まで巻き戻してグラフ状態を再構成できる。

- `search_started`
- `node_discovered`
- `node_updated`
- `node_expanded`
- `goal_found`
- `iteration_exhausted`
- `search_completed`
- `search_failed`
- `search_cancelled`

巻き戻しは表示だけを変え、バックエンドの探索状態を過去へ戻さない。再実行には新しい探索セッションを作る。

### 4.4 ベクトル演算画面

式はフォームビルダーを基本とし、必要に応じてテキスト式も同期表示する。

許可する演算は以下とする。

```text
vector + vector
vector - vector
vector * scalar
scalar * vector
vector / non_zero_scalar
```

各 `vector` は単語ベクトルまたは括弧付きの中間結果である。次は禁止する。

```text
word * word
word / word
scalar / vector
vector + scalar
vector - scalar
```

単語同士の乗算・除算は、標準的なWord2Vecの意味演算ではないため初版では提供しない。要素積などを将来追加する場合は「実験的演算」として別名・別UIにし、通常の乗除と誤認させない。

#### 結果

- 計算後ベクトルのL1/L2ノルム、最小、最大、平均、標準偏差
- 近い単語ランキング上位 `n` 件。既定20、最大200
- 入力に使った単語を結果から除外する切替。既定ON
- 各候補のコサイン類似度、角距離
- 式、モデルID、実験セッションID、計算日時、除外条件
- JSON/CSV出力

スカラー除算の分母が0または許容誤差以下の場合は拒否する。計算後ベクトルがゼロ、非有限値、または次元不一致の場合もランキング処理へ進めず、理由を表示する。

### 4.5 単語パラメータ画面

単語を選ぶと以下を表示する。

- キー文字列、語彙インデックス、ベクトル次元
- モデルが保持する場合の頻度・カウント
- L1/L2ノルム、平均、標準偏差、最小、最大、ゼロ成分数
- 全成分のページング可能な表：`dimension`, `base_value`, `edited_value`, `delta`
- 成分折れ線、値のヒストグラム
- 値が大きい正方向・負方向の成分。ただし次元番号自体に固有の意味はない旨を表示
- 類似語ランキング
- 基底モデルとの差分状態

「パラメータ」は単語ベクトルの各成分と付随統計を指す。学習率やwindow幅などの学習時ハイパーパラメータは、モデルにメタデータとして保存されている場合のみ読み取り表示する。値を推測しない。

### 4.6 実験的編集

編集は必ず実験セッション内で行い、基底モデルを直接変更しない。

対応操作：

- 指定次元の値を設定
- 指定次元へ差分を加算
- ベクトル全体をスカラー倍
- L2正規化
- 他の単語ベクトルまたは任意ベクトルとの差分を加算
- 1語をリセット
- セッション全体をリセット
- 差分をJSONとして出力・再適用

編集前に元値、編集後、変化量をプレビューする。確定後は同じ実験セッションIDを伴う類似語、距離、演算、探索、射影へ一貫して反映する。

既定では実験セッションはメモリ内保存、最終アクセスから60分で失効する。永続化を追加する場合も保存対象は差分とメタデータのみとし、元モデル全体を複製しない。

### 4.7 類似語ランキング

- 正の単語、負の単語、任意ベクトルのいずれかをクエリにできる
- 上位件数、除外語、最小類似度、頻度下限を指定可能
- 表示列：順位、単語、コサイン類似度、コサイン距離、角距離、頻度（存在時）
- 行選択から単語詳細、距離比較、探索の開始・目標へ送れる
- 同点は語彙インデックス、その後キー文字列の順で安定ソートする

### 4.8 距離比較

2〜50語を選び、次を表示する。

- ペア一覧
- コサイン類似度行列
- コサイン距離行列
- 角距離行列
- 生ベクトルのユークリッド距離行列
- L2正規化後のユークリッド距離行列

生ベクトルのユークリッド距離はノルムの影響を受け、モデル間比較に直ちに使えない旨を画面に表示する。OOVを含む場合、黙って除外せず該当語ごとにエラーを返す。

### 4.9 2D/3D可視化

#### 入力集合

- 手動選択語
- 類似語ランキング結果
- A*探索の発見済みノードまたは最終経路
- ベクトル演算結果と近傍語

#### 射影方式

- PCA：既定。決定的で高速
- t-SNE：局所構造観察用。シードとperplexityを保存
- UMAP：任意依存。シード、近傍数、最小距離を保存

2Dは散布図、3Dは回転・ズーム可能な散布図とする。開始語、目標語、経路、編集済み単語、演算結果を別スタイルで示す。結果には手法、パラメータ、対象語順、モデルID、モデルハッシュ、実験セッションIDを含める。

低次元射影では距離・近傍関係が歪む。特にt-SNE/UMAPの軸や離れたクラスタ間距離を意味として解釈できない旨を常時確認できるようにする。異なる対象集合から別々に計算した座標を直接比較しない。

### 4.10 モデル管理

一覧には以下を表示する。

- モデルID、表示名、状態
- 語彙数、次元数、推定メモリ量
- ファイルサイズ、SHA-256
- 形式、作成者、配布元、ライセンス、コーパス情報
- 登録日時、最終読み込み日時
- 正規化方針、既定モデルか否か

操作は登録、検証、読み込み、既定化、アンロード、削除とする。読み込み中のモデルは状態と進捗を表示する。既定モデルの切替は原子的に行い、進行中ジョブは開始時のモデル参照を使い続ける。

アップロードで許可する初版形式は、Gensimの `load_word2vec_format` で安全に読めるword2vec text/binaryと、アプリ独自の安全なメタデータJSONに限定する。信頼できない `.kv`、pickle、任意Pythonオブジェクトをアップロードから読み込まない。管理者がローカル設定で既存 `.kv` を指定する機能は、ファイルが信頼済みであることを前提とする。

## 5. A*連想探索の厳密仕様

### 5.1 グラフ定義

モデル語彙を頂点集合 `V` とする。単語 `u` から、指定された近傍方式、`k`、フィルター、実験セッションで得た上位 `k` 語へ有向辺を張る。

```text
G_k = (V, E_k)
E_k = {(u, v) | v is in top-k-neighbors(u)}
```

近傍関係は一般に対称ではないため、`G_k` は有向グラフである。同じ探索中はモデル、実験差分、`k`、フィルター、近傍インデックスの世代を固定する。

### 5.2 コストとヒューリスティック

既定では以下を用いる。

```text
d(u, v) = angular_distance(vector(u), vector(v))
c(u, v) = lambda + (1 - lambda) * d(u, v)
h(u)    = (1 - lambda) * d(u, goal)
f(u)    = g(u) + h(u)
0 <= lambda <= 1
```

`lambda` は1手ごとの固定ペナルティである。値が大きいほど短い経路を優先し、値が小さいほど各遷移の意味的近さを重視する。既定値は0.15とする。

### 5.3 保証できること

正規化非ゼロベクトルに対する角距離は三角不等式を満たす。そのため上記 `h` は上記 `c` に対して許容的かつ整合的である。

次の条件をすべて満たす場合、A*は固定された `G_k` 内で最小コストの開始語〜目標語経路を返す。

1. 開始語と目標語が語彙に存在する。
2. 目標語が開始語から `G_k` 上で到達可能である。
3. 探索中にモデル、編集差分、近傍定義、フィルターを変更しない。
4. 最大展開数、時間、メモリ、キャンセルで探索を打ち切らない。
5. 同一ノードのより小さい `g` を正しく更新し、優先度キューの古い要素を無視する。
6. 使用する近傍結果が探索中に決定的かつ固定されている。

保証は「Word2Vec空間で真に意味のある最良連想」ではなく、指定条件で構築した有限グラフ内の、定義済みコストに対する最適性である。

### 5.4 保証できないこと

- 上位 `k` の外にある語を含む、より直感的な経路の発見
- 異なる `k`、フィルター、モデル間での最適性
- ANNが返さなかった真の近傍を含む経路
- タイムアウトまたは最大展開数で打ち切った結果の最適性
- 人間にとって自然、因果的、公平、常識的な連想であること
- ヒューリスティックを重み付けして `f = g + w*h`、`w > 1` とする高速モードでの通常の最適性

高速モードを将来提供する場合は「Weighted A*」と明記し、通常モードと結果保証を混同しない。

### 5.5 到達を重視する戦略

既定ではprogressive wideningを使う。`k = 10, 25, 50, 100` の順に、それぞれ独立した固定グラフ探索として最初から再実行する。

- 各段階で到達した場合、その段階の `G_k` 内では最適経路である。
- 前段のopen/closed setを次段へ流用しない。
- どの段階で到達したかを結果に記録する。
- 上限まで失敗しても「語彙全体で経路がない」とは断定しない。

目標語を強制的に近傍へ混ぜると直接辺ができ、連想探索の意味を壊すため、通常モードでは行わない。将来「救済ブリッジ」を追加する場合は、強制追加された辺を視覚的・データ的に区別し、その結果をA*の自然近傍経路として扱わない。

### 5.6 到達不能・失敗ケース

| コード | 条件 | UI表示 |
|---|---|---|
| `START_OOV` | 開始語が語彙にない | 候補語とモデル名を表示 |
| `GOAL_OOV` | 目標語が語彙にない | 候補語とモデル名を表示 |
| `FILTERED_ENDPOINT` | フィルターが開始語または目標語を除外 | 該当フィルターを表示 |
| `NO_ROUTE_IN_GRAPH` | open setが空になった | 指定 `k` のグラフで到達不能と表示 |
| `MAX_EXPANSIONS` | 展開上限に到達 | 最良候補と残件数を表示 |
| `TIMEOUT` | 時間上限に到達 | 経過時間と最良候補を表示 |
| `CANCELLED` | ユーザーが中止 | 中止時点までのデータを保持 |
| `INVALID_VECTOR` | ゼロ、非有限、次元不一致 | 問題の単語または編集を表示 |
| `MODEL_CHANGED` | 必要なモデル世代を保持できない | 再実行を案内 |
| `RESOURCE_LIMIT` | メモリ・イベント数上限 | 具体的な上限を表示 |

失敗時も、最も目標に近かった語、そこまでの暫定経路、展開数、最小 `h`、使用条件を返す。ただし暫定経路を成功経路と表示しない。

### 5.7 擬似コード

```python
def astar(start, goal, neighbors, cost, heuristic, limits, emit):
    open_heap = [(heuristic(start), 0.0, 0, start)]
    came_from = {}
    g_score = {start: 0.0}
    sequence = 1
    closed = set()

    while open_heap:
        check_cancel_timeout_and_limits()
        f_value, queued_g, _, current = heappop(open_heap)

        if queued_g != g_score.get(current):
            continue  # 更新前の古いキュー要素
        if current in closed:
            continue

        emit("node_expanded", current=current, g=queued_g,
             h=heuristic(current), f=f_value)

        if current == goal:
            return reconstruct(came_from, current)

        closed.add(current)

        for neighbor in stable_neighbors(current):
            tentative_g = queued_g + cost(current, neighbor)
            if tentative_g >= g_score.get(neighbor, inf):
                continue

            came_from[neighbor] = current
            g_score[neighbor] = tentative_g
            sequence += 1
            heappush(open_heap, (
                tentative_g + heuristic(neighbor),
                tentative_g,
                sequence,
                neighbor,
            ))
            emit("node_discovered_or_updated", ...)

    return no_route()
```

浮動小数点の完全一致ではなく、実装ではキュー登録時の `g` と現在値の比較に小さな許容誤差を使う。tie-breakは `f`, `g`, 発見順の順とし、再現可能にする。

### 5.8 近傍取得と性能

`NeighborIndex` は次のインターフェースを持つ。

```python
class NeighborIndex(Protocol):
    def top_k(self, vector: NDArray, k: int, *, exclude: set[int]) -> list[Neighbor]: ...
    @property
    def generation_id(self) -> str: ...
    @property
    def exact(self) -> bool: ...
```

- 小規模モデル：Gensim/NumPyによるexact検索
- 大規模モデル：任意のANNインデックス。インデックス構築条件と精度設定をメタデータ化
- 探索中の同一語・同一条件の近傍をLRUキャッシュ
- 編集済みベクトルがある場合、ANNの古いインデックスだけで確定しない。候補取得後に正確な再ランキングを行い、編集語が多い場合はexactへフォールバックする。
- ANN使用時の最適性は「その探索で固定された近似グラフ内」に限定される。

## 6. バックエンド詳細

### 6.1 ModelRegistry

責務：

- モデルファイルとメタデータの登録・検証
- 読み込み、アンロード、既定モデル切替
- SHA-256による同一性確認
- 読み取り中モデルの参照カウント管理
- 近傍インデックス世代との対応管理

モデル状態は `registered`, `validating`, `ready`, `loading`, `loaded`, `error`, `unloaded` とする。エラー時は内部スタックトレースを直接返さず、エラーIDと安全な説明を返す。

### 6.2 VectorService

責務：

- 語彙照会、ベクトル取得、統計量
- 類似語、距離行列、ベクトル演算
- 基底ベクトルと実験差分の合成
- ゼロ・非有限・次元不一致の検証

内部計算は原則 `float32`、集計や累積コストは必要に応じて `float64` を使う。API JSONへ非有限値を出力しない。

### 6.3 ExperimentStore

```text
ExperimentSession
  id: UUID
  model_id: string
  model_sha256: string
  created_at: datetime
  expires_at: datetime
  revision: integer
  edits: map[word, VectorPatch]
```

更新は `revision` を使った楽観ロックとする。クライアントの `expected_revision` が一致しなければ409を返す。モデルハッシュが変わったセッションを別モデルへ黙って適用しない。

### 6.4 SearchJobStore

探索は非同期ジョブとして実行する。初版は単一プロセスのメモリ内ジョブストアでもよいが、インターフェースは永続キューへ差し替え可能にする。

- 状態：`queued`, `running`, `paused`, `succeeded`, `failed`, `cancelled`, `expired`
- イベントに単調増加する `sequence` を付ける
- イベント保持上限に達した場合、古い詳細イベントをスナップショットへ圧縮し、欠落範囲を明示する
- 完了結果は既定24時間保持
- キャンセルは協調的に行い、近傍計算の区切りで確認する

### 6.5 ProjectionService

- 入力順と重複処理を固定する
- PCAは同じ入力・設定で同じ結果を返す
- t-SNE/UMAPは必ずシードを要求または既定値を記録する
- 対象語が2語未満なら拒否する
- t-SNEのperplexityなど、サンプル数に対して無効な値は422で説明する
- 編集後ベクトルを含む場合は結果キャッシュキーに実験revisionを含める

### 6.6 キャッシュ

キャッシュキーに最低限、モデルSHA-256、実験revision、操作種別、語順、パラメータ、フィルター、インデックス世代を含める。モデル切替や編集後に古い結果を返さない。

## 9. モデル・データの取り扱い

### 9.1 モデルメタデータ

最低限、次を保持する。

```json
{
  "display_name": "Japanese sample vectors",
  "source_url": "https://example.invalid/model-page",
  "creator": "...",
  "license_spdx": "UNKNOWN",
  "license_text_url": null,
  "training_corpus": "不明",
  "training_parameters": {},
  "language": "ja",
  "tokenization": "不明",
  "normalization_policy": "none",
  "redistribution_allowed": null

```

不明な値を推測で補完しない。ライセンスが不明な場合は `UNKNOWN` と表示し、再配布不可として扱う。

### 9.2 ファイル検証

- 設定可能な最大アップロードサイズを超えたら413
- 拡張子だけでなく内容・次元・行数・有限値を検証
- 圧縮ファイルを許可する場合、展開後サイズ、ファイル数、パストラバーサル、シンボリックリンクを検査
- モデル名を保存パスとして直接使わず、サーバー生成IDを使う
- 一時ファイルから検証済み領域への移動は原子的に行う
- 検証失敗時は途中生成物を回収する
- SHA-256は読み込み前後で照合する

### 9.3 メモリ管理

- 読み込み前にファイルサイズと語彙×次元から推定メモリを表示
- 設定上限を超えるモデルは読み込みを拒否
- 同時に常駐できるモデル数・総メモリを設定可能にする
- 使用中モデルをアンロードしようとした場合は409、または新規受付停止後に参照がなくなるまで待つ
- OOMでプロセス全体が落ちないよう、可能なら別プロセスで検証・読み込みする

## 10. Word2Vecの解釈上の限界

画面のヘルプ、README、エクスポートメタデータに次を明記する。

1. Word2Vecはコーパス内の共起傾向を学ぶ。辞書的意味、真偽、因果、人間の連想そのものを学ぶわけではない。
2. 類似度は同義性だけでなく、対義語、同じ話題、固有名詞、文体、頻度などを反映し得る。
3. ベクトル演算は線形な規則性を観察する実験であり、常に一貫した意味結果を返す保証はない。
4. 各次元は一般に回転可能で、単独の次元番号へ安定した人間的意味を割り当てられない。成分編集は探索実験であって「意味パラメータの直接編集」ではない。
5. コーパスの偏り、差別表現、古い情報、誤記、過剰代表・過少代表が結果へ反映される。
6. 頻出語、分かち書き、表記揺れ、語彙切り捨て、学習条件に結果が強く依存する。
7. 2D/3D射影は情報を失い、見た目の近さが元空間の距離を正確に保つとは限らない。
8. 異なるモデルの生ベクトルや次元を、そのまま座標ごとに比較できない。
9. A*が返す経路は定義した近傍グラフとコスト上の結果であり、人間の思考順序や唯一の連想経路ではない。

センシティブな語の結果を人物評価、採用、与信、医療、法的判断などに使用しないよう注意を表示する。

## 11. 著作権・ライセンス・利用条件

### 11.1 原則

- アプリ本体のライセンスと、モデル、コーパス、可視化ライブラリのライセンスを分けて管理する。
- 学習元コーパスを入手できることと、学習済み重みを再配布できることは同義ではない。
- Wikipedia等を使う場合も、本文ライセンス、帰属、履歴、商標、データベース権、各モデル配布者の追加条件を確認する。
- モデルファイルをリポジトリ、Dockerイメージ、リリース成果物へ同梱する前に、再配布条件を確認する。
- ライセンス不明のモデルは同梱・公開配布しない。
- ユーザーが持ち込んだモデルはローカル処理を既定とし、外部へ自動送信しない。
- エクスポートにはモデル本体を含めず、出典とハッシュを記録する。

### 11.2 UI要件

モデル登録時に、出典URL、作成者、ライセンス、再配布可否、コーパス説明の入力欄を設ける。不明の場合は警告を出すが、ローカルでの私的検証まで一律に妨げない。公開・共有機能を将来追加する場合は、再配布可否を必須判定にする。

### 11.3 免責

本項は実装上の管理要件であり、法的助言ではない。公開・商用利用・モデル再配布の前に、対象法域と個別ライセンスを確認する。

## 12. セキュリティ・プライバシー

- 初版は `127.0.0.1` バインドを既定にし、外部公開は明示設定とする。
- CORSは開発用オリジンを列挙し、`*` と資格情報を併用しない。
- 任意パス読み込みAPIを公開しない。許可ディレクトリまたはアップロード領域だけを扱う。
- pickle等の任意コード実行につながる形式を信頼できない入力から読み込まない。
- 正規表現フィルターはタイムアウトまたは安全な実装を使い、ReDoSを防ぐ。
- ASTの深さ、探索上限、射影点数、語数、アップロード量、同時ジョブ数へ制限を設ける。
- ログへベクトル全体やローカルファイルパスを通常出力しない。
- エラー応答にスタックトレース、環境変数、サーバーパスを含めない。
- エクスポートのCSV式注入を軽減する。
- 外部公開する場合は認証、CSRF方針、TLS、レート制限、監査ログを追加する。

## 13. 非機能要件

### 13.1 再現性

すべての結果にモデルハッシュ、実験revision、パラメータ、シード、アプリ版を付ける。並び順の同点処理を固定する。テスト用fixtureではOSが異なっても許容誤差内で一致させる。

### 13.2 応答性

- UIの入力・パン・ズームを長時間ブロックしない
- 200ms以上の処理は進行状態を示す
- 探索イベントをバッチ描画し、毎イベントで全グラフを再レイアウトしない
- 既定の描画点数上限を5,000とし、超過時はサンプリングまたは集約を明示する
- すべての長時間ジョブをキャンセル可能にする

### 13.3 推奨性能目標

性能はハードウェアとモデル規模に依存するため、合否を隠れた絶対時間だけで判定しない。CIの小型fixtureでは次を目標とする。

- health、語彙候補、単語詳細：p95 300ms未満
- キャッシュ済み類似語上位20件：p95 500ms未満
- 探索開始から最初のSSEイベント：1秒未満
- キャンセル要求から停止状態反映：2秒未満
- 5,000ノード描画時の操作が実用上継続できること

実モデルではベンチマーク時にCPU、RAM、語彙数、次元、exact/ANN、キャッシュ状態を必ず記録する。

### 13.4 アクセシビリティ

- 色だけで状態を区別せず、形・ラベル・凡例を併用
- キーボードで主要操作が可能
- フォーカス表示、適切なラベル、ステータスのARIA live通知
- canvas/WebGL表示と同じ情報を表または一覧でも確認可能
- アニメーション低減設定に対応

### 13.5 観測性

リクエストID、ジョブID、モデルID、モデル世代、処理時間、展開数、キャッシュhit/missを構造化ログへ出す。単語文字列をログに出すかは設定可能とし、既定はローカルのみ。メトリクスとしてジョブ数、失敗理由、メモリ量、近傍計算時間を取得可能にする。

## 14. テスト方針

### 14.1 固定fixture

小さな人工ベクトルモデルをリポジトリに含める。各語の位置と期待近傍が手計算でき、次のケースを含むこと。

- 一意な最短経路
- 同コスト経路
- 有向辺により片方向だけ到達可能
- 到達不能
- OOV
- ゼロベクトル
- progressive wideningで後段だけ到達可能
- 編集によって近傍が変わるケース

fixtureは第三者モデルを切り出さず、プロジェクト用に生成してライセンスを明確にする。

### 14.2 バックエンド単体テスト

- コサイン・角距離・各統計量
- 加減算、スカラー乗除、0除算、禁止演算
- A*の結果をDijkstraと比較
- ランダムな非ゼロベクトルに対するヒューリスティック整合性の性質テスト
- 古いpriority queue要素の無視
- 安定tie-break
- OOV、フィルター、到達不能、上限、キャンセル
- 実験編集の原子性、revision競合、基底モデル非変更
- モデルハッシュとキャッシュ無効化
- 射影の次元・再現性・不正パラメータ
- CSV式注入対策
- 不正モデル、非有限値、巨大AST、危険なパス

### 14.3 API統合テスト

- 主要エンドポイントの正常系・422・404・409・413
- 探索作成からSSE受信、再接続、完了取得
- キャンセル後に追加展開が続かないこと
- モデル切替中の進行ジョブが開始時モデルを維持すること
- 実験セッションのTTLと失効応答
- JSON/CSV/ZIPの内容とメタデータ

### 14.4 フロントエンドテスト

- OOVやAPIエラーが該当入力付近に表示される
- SSEイベントの重複排除と欠番回復
- タイムライン移動で表示状態が正しく再構成される
- 進行中のキャンセル、一時停止、再開
- 禁止された演算式を送信できない
- 編集プレビューとrevision競合処理
- 2D/3D切替、凡例、表へのフォールバック
- キーボード操作と基本アクセシビリティ

### 14.5 E2Eシナリオ

1. fixtureモデルを読み込む。
2. 開始語・目標語を入力し、探索の展開を確認する。
3. ゴール到達後、経路上の語を選んでパラメータを確認する。
4. 1成分を実験編集し、類似語と探索結果が同じセッション内だけで変わることを確認する。
5. `A - B + C` を計算し、ランキングを出す。
6. 結果集合を3D PCA表示する。
7. 探索をJSON/CSVで出力し、モデルハッシュと設定を確認する。
8. セッションを破棄し、基底モデルの結果へ戻ることを確認する。

## 15. 受け入れ条件

### AC-01 モデル管理

- 対応形式のモデルを登録・検証・読み込みできる。
- 語彙数、次元、ハッシュ、ライセンス情報を確認できる。
- 不正形式や上限超過を安全に拒否し、サーバー内部情報を漏らさない。

### AC-02 A*探索の正しさ

- fixtureの全到達可能ケースでDijkstraと同じ総コストの経路を返す。
- 使用したグラフ条件、コスト式、`k`、exact/ANN、打ち切り有無を結果へ保存する。
- 保証条件を満たす成功結果だけが `optimal_within_fixed_graph: true` になる。

### AC-03 探索過程の可視化

- 発見、更新、展開、ゴール、失敗、キャンセルを時系列で確認できる。
- ノード選択で `g`, `h`, `f`, 親、深さ、類似度を確認できる。
- 最終経路と探索済み領域を視覚的かつ一覧で区別できる。
- 少なくとも1回切断したSSEへ再接続し、重複や欠落なく表示を復元できる。

### AC-04 到達不能の説明

- OOV、フィルター除外、グラフ内経路なし、上限、タイムアウト、キャンセルを区別する。
- 失敗時に最良候補と暫定経路を表示するが、成功と誤表示しない。
- progressive wideningの各試行条件と最終結果を確認できる。

### AC-05 ベクトル演算

- 単語ベクトルの加算・減算、スカラー乗算・除算、括弧を評価できる。
- 単語×単語、単語÷単語、0除算、非有限値を拒否する。
- 結果ベクトルの統計と類似語ランキングを表示する。
- 文字列式をPython/JavaScriptの `eval` へ渡さない。

### AC-06 パラメータ閲覧・編集

- 全成分、統計、基底値、編集値、差分を閲覧できる。
- 編集は実験セッションに隔離され、別セッションと基底モデルへ影響しない。
- 編集後の類似語、距離、演算、探索、射影が同じrevisionを使う。
- リセットで基底値と同じ結果へ戻る。

### AC-07 類似語・距離

- 類似語の安定したランキングと、選択語の各距離行列を表示できる。
- 距離定義と生ベクトル距離の注意点を画面から確認できる。
- OOVを黙って除外しない。

### AC-08 2D/3D

- PCAで2D/3D座標を生成し、操作可能な表示と表で確認できる。
- t-SNE、UMAPを有効にした構成では、シードとパラメータを保存する。
- 射影による歪みの注意を表示する。

### AC-09 エクスポート

- 探索、演算、距離、ベクトル、射影をJSONまたはCSV系形式で取得できる。
- モデルハッシュ、ライセンス、設定、アプリ版を含む。
- CSVの文字列セルに式注入対策が適用される。

### AC-10 限界と権利表示

- Word2Vec解釈の限界、A*保証範囲、バイアス、射影の歪みをヘルプから確認できる。
- モデルごとに出典・ライセンス・再配布可否を表示する。
- ライセンス不明モデルを配布成果物へ自動同梱しない。

### AC-11 品質ゲート

- バックエンド・フロントエンドの単体テスト、API統合テスト、主要E2EがCIで成功する。
- lint、型検査が成功する。
- fixtureを使った主要操作に重大なアクセシビリティ違反がない。
- READMEに起動方法、モデル追加方法、制約、テスト方法がある。

## 17. Codexへの実装指示

Codexは各Phaseで次の順に作業する。

1. 既存コード、README、設定、テスト、未コミット変更を確認する。
2. 当該Phaseの受け入れ条件をテストへ落とす。

4. fixtureで自動テストを実行する。
5. ブラウザで主要操作とエラー表示を確認する。
6. 変更したAPI、設定、制約をREADMEまたはAPI文書へ反映する。
7. 完了していない受け入れ条件と理由を明記する。

以下を実装上の禁止事項とする。

- 信頼できないモデルをpickleとしてロードしない。
- ベクトル式に `eval` を使わない。
- 基底 `KeyedVectors` を実験編集で直接書き換えない。
- OOV、到達不能、上限中断を同じ「見つかりません」にまとめない。
- `1 - cosine` を三角不等式が必要なヒューリスティック保証の根拠にしない。
- ANN結果をexact結果として表示しない。
- モデルライセンスを推測しない。
- t-SNE/UMAPの2D/3D距離を元空間の距離として説明しない。

## 19. Definition of Done

初版は、次の全項目を満たした時点で完了とする。

- AC-01〜AC-11を満たし、証拠となる自動テストまたは確認記録がある。
- fixtureと少なくとも1つの利用許諾を確認した実モデルで主要フローを確認済みである。
- A*結果に保証範囲と終了理由が表示される。
- 実験編集が基底モデルを変更しない。
- 単語同士の乗算・除算を通常演算として提供していない。
- JSON/CSV出力から主要結果を再検証できる。
- モデルの出典・ライセンスとWord2Vec解釈の限界を利用者が確認できる。
- セットアップ、起動、テスト、モデル登録、既知の制約がREADMEに記載されている。
